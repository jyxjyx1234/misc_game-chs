# Siglus_Script_Tool

纯python（其实用了一个官方泄露的exe）打造的Siglus脚本工具。

本工具参考了此前siglus engine泄露的源码，以及一系列前人的工具。

本工具实现了不依赖运行游戏主程序获取密钥，也就是说当游戏无法被破解时，也能提取文本。同时，本工具回封的封包是不加密的，所以可以直接使用体验版未加drm保护的siglusengine.exe来启动，无需换密钥。

本工具还对ss脚本进行了反汇编，从而能够将断句拼接为完整的句子，以及对文本进行分类防止翻译到文件名、音乐名等不应该翻译的文本，更加适合机器翻译。

## 计算密钥

使用`SiglusSceneDecoder_en.exe`，从pck中获取源码文件，找到`暗号.dat`，复制到程序根目录。使用`gen_key.py`可以获取到16字节的密钥。

这个脚本仅需要在你想使用其他工具的工作流时使用。使用本工具的工作流解包`scene.pck`和封包`scene.pck`时，会自动进行解密。

## 解密pck文件

同样需要将`暗号.dat`复制到根目录。在`undec_pck.py`的头部可以设置输入和输出文件名。运行`undec_pck.py`，可以生成未加密的pck文件。只要exe版本号正确，未加密的pck文件可以被任意的sigusengine.exe读取，所以可以不用替换密钥。（也就是说可以直接用体验版exe来替换正式版的加壳exe）

这个脚本仅需要在你想使用其他工具的工作流时使用。使用本工具的工作流解包`scene.pck`和封包`scene.pck`时，会自动进行解密。

（注意，gameexe.dat也需要进行解密。用unpack_gameexe_dat和repack_gameexe_dat重新打包就是解密后的了，没单独写脚本）

## 解包pck文件

使用`unpack_pck.py`将`scene.pck`中的.ss虚拟机脚本解包。文件路径的参数可以在`unpack_pck.py`开头更改。解包时会自动进行解密，所以同样需要将`暗号.dat`复制到根目录。

ss文件后续可以使用本工具中的其他脚本进行提取文本和重构，并使用`pack_pck.py`进行重复封包。

## 提取ss中的文本

使用`dump_ss.py`可以提取ss脚本中的文本。文件开头可以配置路径。

尽管正常对话的文本可以稳定的提取，但是游戏中还会存在许多其他的文本，比如选项和一些UI。考虑到siglus版本的多样性，一些虚拟机函数的特征码可能不同，所以需要自行寻找特征码，参见`dump_ss.py`开头的注释。第一次运行此脚本，会生成一个ss_opcodes的文件夹，里面反汇编了ss脚本中的命令。可以在其中搜索想找的文本，获取其特征码，填入`dump_ss.py`中的对应位置。或者，运行后也会生成一个`not_translated_strings.json`文件，按照特征码对没有提取的特殊文本进行分类。游戏中每类文本的特征码应该几乎是相同的，所以这个工作量不会很大。

同样，可能有部分脚本因为未知原因，无法完整反汇编，此时只会对文本进行简单的筛选，然后提取到`手动处理文本`文件夹中。在其中手动将需要翻译的部分进行翻译即可。

## 回封ss中的文本

使用`rebuild_ss.py`可以将文本封回ss文件。文件开头可以配置路径。`手动处理文本`文件夹中翻译的文本也要进译文文件夹内。

## 封包pck文件

使用`pack_pck.py`进行重新封包。文件路径的参数可以在`pack_pck.py`开头更改。封包的文件默认为无加密的，可以被版本正确的任意加密的Siglusengine.exe读取。还可以调节是否保留源代码文件，如果删除可以减小发布的体积。

## 解包gameexe.dat

使用`unpack_gameexe_dat.py`可以解包gameexe.dat。文件开头可以配置路径。

程序会自动进行解密，需要将`暗号.dat`放入程序根目录。

## 封包gameexe.dat

使用`repack_gameexe_dat.py`可以解包gameexe.dat。文件开头可以配置路径。

此脚本生成的是未加密的gameexe.dat，可以被版本正确的任意的sigusengine.exe读取，无需进行换密钥操作。
